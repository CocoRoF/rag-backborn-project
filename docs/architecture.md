# 구조 메모

읽는 순서: `models/storage.py` → `services/chunking.py` → `services/indexing.py`
→ `services/retrieval.py` → `services/chat.py`.

## 세 층으로 나뉜 저장소

```
Repository        에이전트가 연결하는 단위. 개별 파일에는 연결하지 않는다.
└ StorageNode     사람이 정리하는 것 (폴더/파일). path 는 실체화된 절대 경로.
  └ DocSection    문서 자신의 머리글 계층. 요약 + 임베딩을 가진다.
    └ Chunk       검색되는 잎.
```

`StorageNode.path` 를 실체화해 둔 이유: 하위 트리 스코프가 `path LIKE '/a/b/%'` 한 줄이 되고,
path 정렬만으로 트리가 표시 순서대로 나온다. 대신 이름 변경·이동은 하위 트리 UPDATE 한 번을
치러야 하고, 그 규칙을 지키기 위해 **`path` 를 쓰는 곳은 `services/storage.py` 하나뿐**이다.

## 왜 섹션까지 임베딩하나

조각 임베딩만으로는 "질문이 문서의 어휘가 아니라 저자의 어휘로 되어 있을 때" 아무것도 못 찾는다.
"배포 절차 알려줘" 라는 질문과 "릴리스 파이프라인" 이라는 섹션은 어느 문장 수준에서도 겹치지 않는다.
반대로 "왕복 배송비 얼마?" 같은 질문은 섹션 요약이 아니라 그 한 문장이 정답이다.
둘 다 색인하는 것이 계층의 존재 이유다.

조각을 임베딩할 때 머리글 경로를 본문 앞에 붙인다. 그렇게 하지 않으면 "24개월" 만 담긴 조각은
"숫자에 대한 벡터"가 되고, 붙이면 "그 문서 그 장의 그 숫자에 대한 벡터"가 된다.

## 두 가지 루프 모양

`ChatModel.native_loop` 하나로 갈린다.

- **Claude Code CLI (`native_loop=True`)** — CLI 가 스스로 도구 루프를 돈다. 우리는 턴을
  `services/runtime.py` 에 등록하고, CLI 가 스폰한 `mcp_bridge.py` 가 루프백 HTTP 로 돌아와
  `api/internal_mcp.py` 에서 도구를 실행한다. 턴 토큰은 턴이 살아 있는 동안만 유효하다.
- **HTTP 공급자 (`native_loop=False`)** — 도구 호출에서 멈추고 `services/chat.py` 가 결과를
  붙여 다음 라운드를 돌린다.

두 경우 모두 이벤트 스트림 모양은 같아서, 프론트엔드와 기록 로직은 어느 쪽인지 모른다.

## 스트리밍과 세션

`run_turn` 은 요청의 DB 세션을 빌리지 않고 자기 세션을 연다. 스트리밍 응답은 엔드포인트보다
오래 살고, 스트림 도중에 정리된 세션은 재현하기 가장 어려운 곳에서 터진다.

## 실패해도 되는 것과 안 되는 것

- 임베딩 키 없음 → **색인 성공**, 벡터 없이. 세 개의 어휘 축이 남는다.
- 재순위 실패 → 원래 순위로 답한다. 랭킹 품질만 잃고 답변은 잃지 않는다.
- 섹션 요약 실패 → 첫 문장들로 대체하고 그 문서의 나머지 요약은 포기한다
  (한 번 실패했다는 것은 공급자가 죽었다는 뜻이고, 나머지도 같은 이유로 실패한다).
- 파서 실패 / 텍스트 없음 → 파일 상태 `failed`, 이유를 화면에 남긴다. 조용히 비어 있지 않다.
